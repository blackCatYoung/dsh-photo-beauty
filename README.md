# dsh-photo-beauty · 美颜工坊

在 DeepSeek Harness 里修人像：磨皮、提亮肤色、**人物提亮（整个主体的皮肤）**、**皱纹修复（0–100 淡化 + 涂抹式消除笔）**、**整体肤色（色温 + 色调 2D 盘）**、瘦脸、大眼、化妆（眼影 / 眼线 / 腮红 / 口红）、**液化**（推移 / 膨胀 / 收缩）和**补皮肤画笔**。渲染、检测、参数计算和导出全部在本机完成，不上传图片、不调用模型。面板底色直接取 DeepSeek Harness 当前的调色板，跟随 DSH 的浅色 / 深色 / 第三方主题。

> ⚠️ **装完还要跑一次 `./scripts/setup-engine.sh`**，它会建插件自己的 `.venv` 并装好 MediaPipe / OpenCV（约 300 MB）。没跑这一步，面板会提示 `Beauty engine is not ready`。命令在下面的[安装](#安装)里。

## 它是什么

- **侧栏面板「美颜工坊」**：拖入、粘贴或一次选择多张照片（再导入一批会替换当前这批，全部删掉就回到空白）；预览下方的缩略图条横向滚动，点一张就切换当前图，每张图各自保留滑块、笔画和缩放位置。拖滑块实时看前后对比；滚轮以指针为中心缩放、拖动平移、双击还原。
- **不丢工作**：切到别的侧栏页面再回来，所有照片和它们各自的滑块、色温色调、液化笔画、补皮肤笔画、缩放位置都会恢复。快照只存在当前标签页的 `sessionStorage`，关掉标签页就清空，不会写进缓存或上传。
- **导出**：点右上角「导出」（或 `⌘S`），先勾选要导出的照片（可多选、默认勾当前这张），再选一个 macOS 文件夹，最后逐张按原始分辨率导出并列出结果；挑过的文件夹下次会记住，可以一键在 Finder 里打开。取消不会写文件，也不会改动原照片。
- **化妆**：眼影、眼线、腮红、口红四层，每层独立强度 + 取色器选颜色；按五官关键点直接上色，只动这张脸，不会糊到头发、眼镜或背景。颜色按上一次的选择记住，下次打开面板或换照片仍然是它。
- **人物提亮**：先分割出画面主体，再把这个人**所有露出来的皮肤**（脸、脖子、肩膀、手臂）一起提亮，而不是只把脸刷白；面板会显示主体占画面多少、脸和身体各占多少皮肤。分割偶尔漏掉的边角，用人物提亮右侧的**画笔**直接涂进遮罩，滚轮调笔刷大小。
- **皱纹修复**：0–100 的细纹 / 表情纹淡化，只作用在面部皮肤上，眉毛眼睛嘴唇不动；旁边的**画笔**把涂到的皱纹直接抹平——滑块负责「淡」，画笔负责「净」，滚轮调笔刷大小、`⌘Z` 撤销、抬手才重渲，和补皮肤画笔完全同一套操作。
- **整体肤色**：一块 2D 盘，上下调色温、左右调色调，只改 Lab 的 a*/b* 两条色度轴；范围收在正常肤色里，脖子和手臂跟着一起走，头发、衣服和背景不染。
- **液化**：推移 / 膨胀 / 收缩三种笔刷，拖动时画面**实时跟着变形**（屏幕空间近似），抬手后按原图分辨率重渲；每一笔都能撤销 / 重做，保存和放大查看都按原图坐标重放。
- **一键修图**：点面板右上角的「✨ 一键修图」，先选「当前图片」还是「所有图片」；选所有图片时逐张计算并直接应用，已有的液化和笔刷笔画原样保留。本机先算肤色、脸型、五官比例等指标，再由内置的「人像美颜量化标准」公式直接算出 16 个参数，全程不传图、不调模型。默认风格是「冷粉精致」，但参数按人脸比例计算：瘦脸由 `jaw_ratio/face_aspect/chin_ratio` 代入公式，大眼由 `eye_aspect` 代入公式，肤色按 `a*/b*` 回调；小主体还会按 `subject_ratio` 连续补偿，避免远景小脸永远停在 10 左右；不同脸型、不同眼裂会得到不同数值，不是固定值。卡片里显示理由、指标差异和计算耗时，点「应用」即可看到效果，随时撤销。
- **对话工具 `beauty_retouch`**：直接让模型修图，例如「把这张照片磨皮 40、提亮一点、整体肤色暖一点、下颌收窄、涂个豆沙色口红」，工具会返回成品路径和预览图。

技术栈：MediaPipe FaceLandmarker（478 点）+ MediaPipe 多类人像分割（整图主体 + 脸部 hair / face-skin / body-skin）+ OpenCV。瘦脸/大眼用 landmarks 构造平滑位移场 + `cv2.remap`；皮肤范围用分割模型逐像素判定，磨皮用导向滤波做肤色区高频分离；提亮在 Lab 空间抬 L、压饱和度，整体肤色则只动 a*/b* 两条色度轴，L 保持不变。

## 安装

```bash
# 1. 拿到插件目录后，准备本地引擎（约 300 MB，只装进 .venv）
./scripts/setup-engine.sh

# 2. 装进 DSH 的 web profile
dsh plugin --profile web add /path/to/dsh-photo-company

# 3. 重启 DSH
```

`setup-engine.sh` 会挑一个 ≥3.10 的 Python 建 `.venv`，安装 `mediapipe / opencv-python-headless / numpy / pillow`，并下载两个模型到 `engine/models/`：3.6 MB 的 FaceLandmarker 和 16 MB 的多类人像分割模型。系统 Python 不会被改动。

也可以手动指定解释器：插件配置 `python: "/path/to/python"`，或环境变量 `DSH_BEAUTY_PYTHON`。候选顺序：配置 → 环境变量 → `<插件>/.venv/bin/python` → `python3`。

| 皱纹修复 wrinkle | 把面部皮肤的细纹、眼尾纹、法令纹提回周围肤色；100 仍保留毛孔，不会抹成一片白 | 20–60（0–100） |

| 眼影 shadow | 上眼睑到眉骨的渐变晕染，带一点外眼角飞尾；右上色块选颜色 | 20–55 |
| 眼线 liner | 贴着睫毛根部、跟着眼型走的一条细线，内眼角收细、到外眼角为止，不上挑 | 10–50 |
| 腮红 blush | 颧骨上的椭圆柔化，乘皮肤 mask，不碰头发和镜框 | 20–45 |

- 预设：自然 / 柔光 / 通勤 / 晚宴，四套风格拉开：自然几乎看不出妆，柔光给奶油肌和蜜桃气色，通勤收轮廓、眼线利落，晚宴冷调梅子浓妆。每套都带自己的妆色和肤色盘位置。
- 整体肤色盘：上下是色温（上暖下冷），左右是色调（左绿右洋红），中间的十字是中性。点一下或按住拖动都能落点，方向键 ±1、Shift + 方向键 ±5，双击或「归零」回中性；读数是「暖 +6 · 洋红 +3」这种直接能看懂的文字。它只肤色化真正是皮肤的像素（脸 + 主体身体皮肤），眉毛、睫毛、嘴唇、头发和衣服都不跟着变。
- 化妆的颜色是十六进制（`#rrggbb`），取色器改完立刻重渲；四层默认 0，所以不影响只做美颜的老用法。颜色和最近一次的选择存在 `localStorage`，换照片、重开面板都会沿用。
- 底色跟随 DSH 主题：面板没有自己的主题开关，读的是宿主的 `--dsw-alias-*` 调色板（浅色、深色、第三方主题都算），DSH 切主题时整块面板即时跟着换；只有在浏览器里单独打开工作台这一页时才退回跟随系统外观。照片上的角标仍是深色玻璃，保证在亮背景上也看得清。
- 预览长边 2400 px（约 0.38 秒），导出时按原始分辨率重算。
- 放大后预览不够看：预览是 2400 px 的位图，再放大就是插值。面板在预览位图被拉到 1.5 设备像素/预览像素以上时，向 host 要一块当前视口对应的原图裁切（`--crop`，长边上限 2600 px），盖在预览上。这块裁切放在 `.preview-wrap` **外面**的 `#zoomLayer` 里、用屏幕像素定位：wrap 上挂着 `scale()`，放在里面的东西只会按布局尺寸栅格化再被拉伸——就算给的是原图像素也一样糊。停手 220 ms 才请求，拖动/缩放期间沿用上一块裁切（带 15% 余量）跟着位移，不抢渲染。
- 「对比原图」在放大状态下换的是同一块视口的**未修图原生裁切**（`/detail` 的 `mode:"original"`，参数全 0），跟着修图裁切一起预取；100% 时仍用全分辨率原图叠层。
- 导出走 host 侧的原生面板：先 `choose folder` 选目标文件夹，批量写到该文件夹里，重名自动追加 `-2`、`-3`；工具调用或不带 `dir` 的保存仍走 `choose file name`，上次选择的文件夹记在缓存目录的 `settings.json`；取消不会写文件。
- 缩略图由 host 用 macOS `sips` 转成小 JPEG 并缓存（`thumbs/`），HEIC 也能显示；修完一张后，缩略图会换成修好的样子。
- 按住图片或「对比原图」查看修前效果。
- 多张人脸时默认处理第 0 张；工具调用可用 `face` 指定序号。

## 工具调用

```json
{
  "input": "~/Pictures/portrait.jpg",
  "smooth": 35,
  "whiten": 15,
  "slim": 20,
  "eyes": 12,
  "person": 30,
  "wrinkle": 35,
  "temperature": 4,
  "tint": 2,
  "liquify": [
    { "mode": "push", "radius": 0.06, "strength": 0.55, "points": [[0.42, 0.58], [0.46, 0.6]] }
  ],
  "shadow": 40,
  "shadowColor": "#a97b8c",
  "blush": 30,
  "lip": 65,
  "lipColor": "#b4404f",
  "output": "~/Pictures/portrait-beauty.jpg",
  "compare": true
}
```

可选参数：`detail`、`temperature`、`tint`（`warmth` 是 `temperature` 的旧别名，老调用继续有效）、`person`、`wrinkle`、`face`、`compare`、`max_size`、`liquify`、`maskStrokes`、`wrinkleStrokes`，以及化妆四组 `shadow`/`liner`/`blush`/`lip` + `shadowColor`/`linerColor`/`blushColor`/`lipColor`。不传 `output` 时写到缓存目录。

`liquify` 是一个笔画数组，坐标是原图归一化坐标（0–1）：`mode` 为 `push` / `bloat` / `pucker`，`radius` 是原图宽度的比例（0.004–0.6），`strength` 是 0.02–1，`points` 最多 512 个点。面板里画的每一笔都是这个结构，所以导出、放大裁切和工具调用走同一条渲染路径。

`maskStrokes` 是补皮肤画笔的笔画数组，坐标同样是原图归一化坐标：`radius` 是原图宽度的比例（0.002–0.4），`points` 最多 512 个点。它和自动分割出的主体皮肤取并集，所以只会影响**人物提亮**和**整体肤色**的皮肤范围，不会改动磨皮或化妆。

`wrinkleStrokes` 是皱纹修复笔的笔画数组，结构和 `maskStrokes` 完全一样（`radius` 0.002–0.4、`points` 最多 512 个归一化点）。它和 `wrinkle` 滑块互相独立：滑块按强度淡化整脸，笔画像局部橡皮一样把涂到的皱纹抹平，两者可以同时给。

### 引擎 CLI 的两种模式

```bash
python engine/beauty.py --input photo.jpg --output out.jpg --smooth 30   # 渲染
python engine/beauty.py --input photo.jpg --detect                       # 只输出 landmarks JSON
python engine/beauty.py --input photo.jpg --output out.jpg --landmarks faces.json  # 复用检测结果
python engine/beauty.py --input photo.jpg --output patch.jpg --crop 2400,1500,2360,1570  # 只渲这块原图
python engine/beauty.py --input photo.jpg --output out.jpg --lip 70 --lip-color "#a3243f" --blush 35  # 只加口红和腮红
python engine/beauty.py --input photo.jpg --output out.jpg --person 45       # 人物提亮（主体全部皮肤，0–100，越往后越亮）
python engine/beauty.py --input photo.jpg --output out.jpg --wrinkle 40      # 皱纹修复：淡化面部细纹（0–100）
python engine/beauty.py --input photo.jpg --output out.jpg --wrinkle-strokes '[{"radius":0.05,"points":[[0.42,0.55],[0.47,0.58]]}]'  # 画笔：把涂到的皱纹抹平
python engine/beauty.py --input photo.jpg --output out.jpg --temperature 8 --tint 2  # 整体肤色：暖一点、略偏洋红
python engine/beauty.py --input photo.jpg --output out.jpg --liquify '[{"mode":"push","radius":0.05,"strength":0.6,"points":[[0.4,0.5],[0.44,0.52]]}]'
python engine/beauty.py --input photo.jpg --output out.jpg --person 40 --mask-strokes '[{"radius":0.04,"points":[[0.12,0.5],[0.2,0.55]]}]'  # 手动把一块皮肤加进遮罩
```

`--crop X,Y,W,H` 在原图坐标里裁一块、按原生分辨率渲染（配合 `--max-size` 限制长边），landmarks 与分割类别图会自动平移到裁剪坐标；面板放大时用的就是它。

`--detect` 与 `--landmarks` 是为速度加的：MediaPipe 每起一个进程要几百毫秒到数秒，而滑块每动一下都要重渲一次。插件在上传时就把 landmarks 和皮肤分割结果一起算好，按「路径 + mtime + 大小 + 缓存版本」存进 `<cache>/landmarks/`；之后每次渲染只把类别图缩放到当前分辨率再跑仿射与滤波（2400 px 预览约 0.38 秒，类别图 PNG 压缩后约 13 KB/张脸）。

小人脸也能找到：整图检测不到时会按约 45% 边长的重叠块重扫一遍（`detect_faces()`），所以全身照、风景人像也能识别。

## 皮肤范围是怎么定的

磨皮和提亮的力度乘在 `skin_mask` 上，所以这张 mask 决定了「哪里算脸」：

1. **分割（主路径）**：每张脸裁一个 1.9×脸宽的方框，跑 MediaPipe `selfie_multiclass_256x256`，取 `face-skin` 类别（3）。发际线、垂在额头的碎发、鬓角、眼镜框因此在像素级别被区分开；额头不再被 landmarks 的 oval 顶边切掉。
2. **约束**：类别图再乘一个以 oval 为准的头脸包围盒（上到发际线以上、下到下巴，左右各放 0.18 脸宽），保证颈部、衣服、背景不会被误提亮。
3. **五官保护**：眉毛、眼睛、嘴（外唇凸包，张开的牙也在内）先按 1.2% 脸宽膨胀再相减，细窄区域能被完整排除——旧版是先羽化再相减，眼角和唇心只能减到 35–70%。
4. **边缘贴合**：类别图按裁剪框原分辨率回传（模型内部是 256 网格），边界先用导向滤波吸附到真实亮度边缘，再按 0.8% 脸宽羽化，发丝缝隙里不会出现硬边。
5. **随瘦脸一起变形**：mask 先于变形生成，再用 `warp_portrait(return_field=True)` 的同一张位移场 `remap`，下颌线不会和磨皮区错位。

瘦脸的位移场按高斯权重归一化：`dx = Σ(wᵢ·moveᵢ) / Σwᵢ`。分母会随距离衰减到 0，直接拿它当除数，场的边界就会从「满强度」一步掉到 0——位移相邻两像素差 20 多像素，画面在那条线上像被撕开，出现一条竖直的白线（重复出来的发丝）。现在把分母钳在峰值的 1/4（`floor = norm.max() * 0.25`），场跟着高斯尾巴平滑归零，边界不再有台阶。

**提亮用的是另一张 mask**：磨皮要避开五官（否则眼角和唇纹会被糊掉），提亮却要盖住五官——只提亮脸颊、把眉毛眼睛嘴唇原样留着，会在脸上留下一圈「没提亮」的深色空洞，对比非常突兀。所以 `tone_weighted` 收到的提亮权重是「分割类别 ∪ 五官区域（膨胀后的眉/眼/唇）」的整脸 mask（`skin_mask_from_segment(..., protect_features=False)`），只在下巴、发际线、鬓角这些真正的外边界收住；`crisp_details` 仍然只锐化非皮肤区。整体肤色走的是相反的选择：色温/色调只乘在**真正是皮肤**的那张 mask 上（脸 + 主体身体皮肤），免得把眉毛和嘴唇也染上一层暖色。

分割模型缺失时自动退回 landmarks oval（`skin_mask()`），并在 `notes` 里写明。想直接看范围，渲染时加 `--mask-out mask.png` 导出 mask。

## 人物提亮：先把主体找出来

「提亮肤色」只动脸，所以脖子、肩膀、手臂还是暗的，人像看上去像只白了一张脸。人物提亮换了一条路：先找出画面里的**主体**，再把这个人所有露出来的皮肤一起提亮。

1. **整图分割**：把长边缩到 640，跑同一个 `selfie_multiclass` 模型，拿到 background / hair / body-skin / face-skin / clothes / others 六类；`person` = 除背景以外的全部。主体在画面里太小时（不到 30%），再按主体 bbox 裁一块、只跑 256 输入的细分：全身照里手臂在整图模型里可能只有几个像素宽，会被误判成衣服；裁出来重跑后，大臂、小臂、手都能回到 body-skin，最后再用连通域贴回主体皮肤，不会把背景里肤色相近的墙或路人手加进来；mask 边缘再按肤色色度向外长几个像素，避免肩带、发际线旁边留一条没提亮的细边。
2. **认主体**：对人像类别做连通域，以人脸中心落在哪个域来判断主体（没有脸时取面积最大的域）。这样合影里站在旁边的人不会被一起提亮。
3. **找皮肤部分**：`主体 ∩ (body-skin ∪ face-skin)`，再挖掉 landmarks oval（膨胀 2% 脸宽），剩下的连通域就是脖子、肩膀、手臂这些身体皮肤——面板上「N 处」就是这个数。
4. **曲线提亮（一次 Lab 变换）**：脸仍然用原来的整脸 mask（含五官），身体用主体皮肤 mask，把「主体皮肤 × person/100」直接当亮度强度。引擎不再做线性加亮，而是按 Photoshop Levels / 曲线里中间调 gamma 的思路弯 L*：`L' = 255·(L/255)^(1/γ)`，`γ = 1 + 2.4·(person/100)^1.2`。γ 随滑块加速增长，所以前半段温和、越往后每一格提亮越多：50 时 γ≈2.0，100 时 γ≈3.4，脸和身体被推到接近纸白但高光仍保留层次；0 和 255 两端固定，高光自然收住，不会像线性加亮那样大片死白。日常人像建议 20–60，逆光或全身照可以拉到 80–100。
5. **报告**：`skin` 字段返回 `face` / `body` / `parts` / `people` / `subject` 五个数，面板显示成「脸 6.8% · 身体 8.4%（3 处）· 主体占画面 41.2%」，用来判断主体有没有找对。
6. **手动补皮肤**：分割再细也会有漏的边角（细肩带旁、逆光的手臂轮廓）。人物提亮右边的「画笔」打开后，直接在照片上涂抹，涂到的像素会并进主体遮罩，抬手重渲；滚轮改笔刷大小（0.6%–20%），`⌘Z` 撤销最后一笔，「清除」全部重来。笔画存的是原图归一化坐标，所以预览、1:1 裁切、整图保存三处涂的是同一块。

头发、衣服、背景不属于皮肤类，所以不会被提亮；深色衣服不会跟着变亮。

## 皱纹修复：补的是明暗，不是换皮肤

皱纹在像素上就是一条**比周围皮肤暗、又窄**的脊。所以这件事只需要两步：先估出「如果这里没有这条脊，皮肤应该是什么亮度」，再把暗脊补回去。

- **低频基准**：把灰度图降采样到 1/4 再跑导向滤波、放大回来。皱纹在 1/4 图上只剩亚像素宽，会一起平滑掉，而脸颊的明暗过渡、鼻梁高光这些大结构都留着。全分辨率直接滤波不行——滤完的基准还带着皱纹本身的暗，减出来的差值接近 0。
- **只提亮，不减暗**：`fill = clip(base - gray, 0, limit)`。方向单一，高光、毛孔、皮肤质感都不会被反向压平；上限 72 灰阶，避免把深法令纹一次性拉成一条白线。
- **强度**：`weight = clip((depth - 1.0) / 5.0, 0, 1)` 把「淡淡的皮肤纹理」和「真的皱纹」分开，再乘 `wrinkle/100` 和 1.25 的增益。50 大约是肉眼可见的淡化，100 是明显淡化但仍像皮肤——滑块不是「修图前后」的开关。
- **只动脸**：权重乘在皮肤分割 mask 上，再乘 `1 − 五官保护`；眉毛、睫毛、眼睑、嘴唇不会被抹平，也不会在眼窝里留下亮斑。
- **修复笔**：和滑块同一套判定，只是更狠——阈值降到 `depth > 0.6`、基准半径放宽到脸宽的 14%（滑块是 10%），所以比滑块更宽、更浅的褶皱也能认出来；认出来之后再叠一次更深（1/8 分辨率）的 `flatten_skin()`，把滑块会剩下的残余填掉。它仍然只动「比周围暗」的像素，平皮肤、毛孔原样保留，所以涂完是「这块皮肤被熨平了」而不是「被磨皮了」。笔迹的羽化跟着笔尖走（`sigma = 笔尖半径 × 0.35`，不再按画面短边算，否则 0.1% 的小笔会被羽化放大成一个 20px 的团），羽化后乘五官保护，涂过眼线、嘴唇也不会擦掉；笔画存原图归一化坐标，预览、1:1 裁切和整图保存抹的是同一块。

试过但没采用的做法：形态学闭运算当基准（会把毛孔、雀斑填成一颗颗亮斑）；中值滤波基准（提亮幅度不够）；把基准整块「替换」回原图（皮肤发灰、发糊）。现在的做法在重皱纹的深肤色人像上（1280×1419，Wikimedia「Elderly Gambian woman」）50 / 100 两档都自然，毛孔和皮肤反光都在。

## 整体肤色：一块盘，两条色度轴

「提亮」只管明暗，可照片里的肤色问题更多是**冷暖**（荧光灯下发青、夕阳下过黄）和**绿/洋红偏色**（混合光源最常见）。iPhone 的摄影风格把这件事做成一块 2D 盘：上下拖调色温，左右拖调色调。这里用的是同一套交互。

- **只动色度，不动明暗**：在 Lab 空间里，色温走 b*（蓝 ↔ 黄），色调走 a*（绿 ↔ 洋红）。L* 一个像素都不碰，所以调完不会像加了一层半透明滤镜那样整体变亮或变灰。
- **范围收在正常肤色里**：±50 时色温最多走 7.5 个 b*、色调最多走 4.5 个 a*——大约是「阴天阴影」到「暖色夕阳」的跨度，正常人像在这个范围内怎么拖都不会变成橙色或紫色。还加了一点交叉项：升温时 a* 轻轻加 0.8，洋红时 b* 轻轻减 0.6，让结果更像皮肤而不是染色的玻璃。
- **只碰到皮肤**：色温/色调乘在「脸的分割皮肤 mask ∪ 主体身体皮肤 mask」上，所以脖子和手臂会跟着走，眉毛、睫毛、嘴唇、头发和衣服不动。
- **和提亮/人物提亮一起算**：三种调整都合进同一次 Lab 往返（`tone_weighted`），脸和脖子不会因为叠加两次而出现色阶。
- **旧参数还认**：`warmth` 是色温的旧名字，工具调用、CLI 和面板读到的旧值都会折进 `temperature`，不会因为升级就丢参数。

## 化妆是怎么画上去的

四层都只用同一套 478 点 landmarks，不引入第二个模型，也不下载贴图。

1. **眼睛坐标系**：`_eye_frame()` 取 `u = 外眼角 − 内眼角`，把「头顶方向」对 `u` 正交化得到 `v`。下面所有几何都在这个坐标系里算，所以头歪一点也不会画偏。
2. **眼影** `eyeshadow_mask()`：上眼睑四点朝外眼角方向依次抬高 0.40 / 0.62 / 0.82 / 0.90 倍「眼睑到眉骨下缘的距离」，外眼角再加一小段飞尾；权重取「到睫毛线折线的距离」的高斯衰减，所以根部最浓、往眉骨自然散开；最后再乘皮肤 mask，眉发和镜框不会跟着染色。
3. **眼线** `liner_mask()`：贴睫毛根部，走的就是上眼睑那四个点的折线：内眼角留出 12% 眼宽（泪阜不是眼睑），线宽从内向外收放，到外眼角就停住并把末端磨圆——不画飞尾，所以线跟着眼睛的弧度走，不会挑出眼型外面。
4. **腮红** `blush_mask()`：以 205 / 425 颧骨点为锚，沿「脸颊外缘 − 鼻翼」方向外移 0.08 脸宽，画 0.19 × 0.115 脸宽的椭圆高斯，再乘皮肤 mask，所以不会糊到头发和镜框。
5. **口红** `lip_mask()`：外唇多边形减内唇多边形，张开的嘴、牙齿、唇缝都不会被染色。

上色不是「盖一层半透明颜色」，而是 `tint_region()`：在 Lab 里把这块区域的**平均 a/b 移到目标色**，逐像素保留原来的明暗变化，所以唇纹、唇峰高光、眼窝阴影都还在；亮度按目标色的 L 往一个方向微调（`lum` 把幅度压到 30–45%），最后按 mask 羽化与原图合成。眼线是唯一例外，用 `paint_solid()` 做不透明混合——眼线本来就是实色。

顺序是 腮红（乘皮肤 mask）→ 眼影 → 眼线 → 口红，都放在磨皮 / 提亮 / 细节之后，用的还是瘦脸大眼变形后的 landmarks，所以妆不会被磨皮糊掉，也不会和变形后的脸错位。

## 液化：笔刷怎么变成像素

1. **面板只记路径**：拖动时记下原图归一化的点、笔刷半径（原图宽度的比例）和强度，画一条高亮轨迹和一个笔刷圈；抬手才发一次 `/render`。4K 图不会在每次 pointermove 都重渲。
2. **引擎重放**：每笔按 `max(半径×0.22, 1.5 px)` 重采样路径；`push` 每段位移是 `(b−a)×strength`，权重 `(1−d²/r²)²`，单点位移上限是 45% 半径；`bloat` / `pucker` 用径向缩放，幅度上限 30%。
3. **只动笔画附近**：`cv2.remap INTER_CUBIC` + `BORDER_REFLECT`，包围盒外扩 1.25 倍半径，背景像素一个都不碰。
4. **实时预览**：拖动时用同一个位移公式在屏幕空间里反向采样当前可见图层（基础预览或放大后的 1:1 裁切），所以笔刷跟着指针走；抬手后由引擎按原图坐标重放并替换掉这层近似。
5. **顺序**：液化放在化妆之后，所以妆会跟着形变走，不会和嘴、眼睛错位。
6. **放大和导出**：放大时的 1:1 裁切会把笔画按 `--crop` 窗口重新映射（`map_liquify_strokes`），导出时按原始分辨率重放，预览和成品一致。
7. **撤销 / 重做**：只存笔画列表，不存位图；`⌘Z` / `⇧⌘Z`，按钮和快捷键都可以。关掉「液化笔刷」后笔画保留，可以继续拖动平移。

## 现成的开源方案（调研结论）

先看了一圈现成实现，实测了 star 数和许可证：

| 方案 | 许可 | 做法 | 为什么没用 |
| --- | --- | --- | --- |
| [ehsanwwe/OpenMakeupSDK](https://github.com/ehsanwwe/OpenMakeupSDK)（33★） | MIT | MediaPipe FaceMesh + Three.js/WebGL，用预制的 PNG 贴图做粉底/口红/腮红/眼线/睫毛/眼影，含瘦脸 | 浏览器端实时 AR 试妆，要美术贴图；和这里的 Python 管线是两套，装进来等于把面板预览和保存结果分成两条路径 |
| [PSGAN](https://github.com/wtjiang98/PSGAN)（782★, MIT）、[CPM](https://github.com/VinAIResearch/CPM)（420★, BSD-3）、[BeautyGAN](https://github.com/Honlan/BeautyGAN)（699★） | MIT / BSD-3 | 给一张参考妆容图做整脸风格迁移（GAN，需要 GPU） | 只能「照着这张图化」，没法按「眼影 40 + 口红 80」分项调；还要额外权重和显存 |
| [Jayanths9/Virtual_Makeup](https://github.com/Jayanths9/Virtual_Makeup)（66★）、[hriddhidey/visage](https://github.com/hriddhidey/visage)（108★, MIT）、[KAlO2/PerfectShow](https://github.com/KAlO2/PerfectShow)（230★, Apache-2.0） | MIT / Apache-2.0 | OpenCV + landmarks（部分 + seamless clone）画口红/眼线/眼影 | 思路和这里一致，但都是独立脚本、参数写死；拿过来还得重写成能被面板和工具共用的一套 |
| [zllrunning/face-parsing](https://github.com/zllrunning/face-parsing.PyTorch)（2595★, MIT）、[yakhyo/face-parsing](https://github.com/yakhyo/face-parsing)（335★, MIT） | MIT | BiSeNet 人脸解析，类别里有 lips / eyes / brows | 会多一个模型（几十 MB）和一次推理；现有 landmarks 已经够定位唇、眼、颊，收益不值这个复杂度 |

结论：**不引入新依赖，用 landmarks 程序化绘制**。理由有三条：面板预览、保存、`beauty_retouch` 工具共用同一条渲染路径，结果必然一致；不用下载模型或贴图；四层强度可以分别给滑块。想要浏览器里实时试妆（不落盘、只预览）的话，OpenMakeupSDK 是最接近的现成选择，可以单独嵌一个 iframe 玩。

## 隐私

- 图片只写到 `~/.dsh/beauty-cache`（缓存，自动保留最近 240 张）和 `~/Pictures/DSH Beauty`。
- 路由只服务缓存内的文件，id 走白名单正则，文件名用固定格式，不接受任意路径。
- 引擎进程的 stdout/stderr 只在出错时截断回显，不写日志文件。
- **完全不联网**。一键修图的参数由本机指标代入公式计算，不上传图片、不调用模型，也没有首次确认弹窗；换一张图只会因为指标不同而得到不同参数。
- 结果卡会写明计算引擎、耗时和「未上传，全部本机计算」。

## 已知限制

- 只处理检测到的第一张脸（或指定序号），不做多人同时优化。
- 侧脸、遮挡、低分辨率时 landmarks 会漂移，瘦脸可能拉扯发际线；调低 `slim` 即可。
- 分割模型对 1–2 px 的细物件（细眼镜框、发丝）分辨不出来，这些像素仍按皮肤处理；粗框眼镜、帽子、口罩会被正确排除。
- 「提亮肤色」滑块仍然只覆盖脸（含五官）；要连脖子、肩膀、手臂一起亮，用「人物提亮」。两者可以叠加。
- 人物提亮依赖分割：主体和背景颜色极接近、或人物被裁得只剩一小块时，边缘可能漏掉几个像素；全身照里的细手臂会走一次主体裁切细分来补（不到 30% 才触发）。仍有边角时用「画笔」手动涂进去；涂到衣服或背景也会被当成皮肤一起提亮，所以画笔要贴着皮肤边缘涂。
- 皱纹修复只对「比周围暗、宽度在基准半径以内」的脊有用：法令纹那种整块阴影、松弛造成的体积起伏不会被抹掉，调高只会让那块变亮而不是变平。半径已经放宽到脸宽的 10%（画笔 14%），再宽的结构就超出「皱纹」的范畴了。
- 液化的实时变形是屏幕空间的近似（按当前缩放层自己算一遍位移），4K 全图抬手重渲后细节可能略有差异；最终导出以引擎渲染为准。
- 液化的笔画是图像坐标：先画液化、再改瘦脸 / 大眼，笔画不会跟着五官移动，需要重新画。
- HEIC 通过 macOS `sips` 转 JPEG 读取；Linux 上不支持 HEIC。
- 首次检测（MediaPipe 冷启动 + matplotlib 字体缓存）约 0.5–8 秒，之后同一张图每次渲染约 0.4 秒；字体缓存固定在插件目录 `.cache/mpl`，不会每次重建。
- 放大后的 1:1 裁切是独立的一次渲染（约 0.4–0.6 秒），只在停手后触发；同一视口 + 同一参数的裁切会在 `render/` 里缓存 10 分钟。对比用的原图裁切是同一块区域再渲一次（0.15–0.3 秒），所以放大时两块裁切的请求是串行的。
- 化妆只认五官位置，不知道眼皮厚薄和双眼皮褶皱走向：笑眯眼、闭眼时浓眼影/眼线可能压到镜框上，调低强度最省事。
- 口红按唇形整片染色，咬唇、渐变唇这种只在唇内侧上色的画法不支持。
- 4K 原图全分辨率渲染约 2–4 秒（7008×4672 实测 2.4 秒）。
